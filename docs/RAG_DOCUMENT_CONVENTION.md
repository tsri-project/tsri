# ข้อกำหนดระบบสารบรรณโครงการ + Document ID + File Naming Convention
## TSRI One Link for All — RAG Knowledge Base Architecture

> **เป้าหมาย:** สร้างมาตรฐานการตั้งชื่อไฟล์ รหัสเอกสาร และโครงสร้างโฟลเดอร์ภาษาไทย เพื่อให้ระบบ AI RAG (Retrieval-Augmented Generation) สามารถ Parsing, Chunking, Indexing และค้นหาความเชื่อมโยงทางกฎหมายและผลผลิตได้อย่างแม่นยำ 100%

## 1. รูปแบบโครงสร้างชื่อไฟล์มาตรฐาน (File Naming Convention)

### รูปแบบ:
```text
[รหัสประเภท]-[หน่วยงาน]-[ลำดับ]-[ปี]_[ชื่อเรื่อง]-[สถานะ].[นามสกุล]
```

### ตัวอย่าง:
- `LAW-NSC-001-2562_พระราชบัญญัติสภานโยบายการอุดมศึกษา-ฉบับใช้บังคับ.pdf`
- `REG-NSC-001-256x_ระเบียบสภานโยบายฯ-ฉบับใช้บังคับ.pdf`
- `REG-PMH-001-256x_ระเบียบคณะกรรมการส่งเสริมวิทยาศาสตร์วิจัยและนวัตกรรม-ฉบับใช้บังคับ.pdf`
- `ANN-PMH-001-256x_ประกาศคณะกรรมการส่งเสริมวิทยาศาสตร์วิจัยและนวัตกรรม-ฉบับใช้บังคับ.pdf`
- `ORD-TSRI-001-2569_คำสั่งสกสว-ที่-บค-7-2569-แต่งตั้งบุคคล.pdf`
- `TOR-PROJ-001-2569_ขอบเขตงานและเอกสารแนบท้ายสัญญา-ฉบับลงนาม.pdf`
- `MOM-PROJ-001-2569_รายงานการประชุม-Kickoff-18-09-2569-ฉบับรับรอง.pdf`

## 5. RAG Metadata Extraction & Vector Embeddings Rule

เมื่อเอกสารเข้าสู่ระบบ AI Parser จะทำการแยก Metadata ดังต่อไปนี้:
1. **Document ID**: `[Prefix]-[Org]-[Seq]-[Year]`
2. **Title**: ชื่อเรื่องภาษาไทย
3. **Hierarchy Level**: ลำดับศักดิ์ของกฎหมาย (ระดับ 1 แม่บท, ระดับ 2 ลำดับรอง, ระดับ 3 แนวปฏิบัติ)
4. **Folder Category**: เส้นทางโฟลเดอร์ (เช่น `01_กฎหมายแม่บท/01.01_พระราชบัญญัติสภานโยบาย`)
5. **Effective Status**: ฉบับใช้บังคับ, ฉบับลงนาม, ฉบับรับรอง, ร่าง, ยกเลิก
6. **Legal Provisions**: แบ่ง Chunking ตาม มาตรา/ข้อ/วรรค เพื่อความแม่นยำในการทำ Semantic Search
